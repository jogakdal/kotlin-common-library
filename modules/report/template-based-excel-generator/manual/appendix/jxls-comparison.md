# TBEG과 JXLS 상세 비교

이 문서는 템플릿 기반 Excel 생성 라이브러리를 선택할 때 참고할 수 있도록, TBEG과 [JXLS](https://jxls.sourceforge.net/)를 기능·성능·편의 측면에서 상세히 비교합니다. **어느 한쪽의 우월을 주장하지 않으며**, 각 라이브러리가 실제로 제공하는 기능과 제약을 사실대로 정리하는 것을 목표로 합니다.

- **비교 대상**: TBEG 1.2.5 (Apache POI 5.5.1) / JXLS 3.1.0 (jxls-poi)
- **기준**: JXLS 항목은 공식 문서에 더해, 불명확한 부분은 JXLS 3.1.0을 직접 구동해 산출물을 검사한 실측으로 확정했습니다. 성능 수치는 동일 환경에서 측정한 자체 벤치마크입니다([성능 벤치마크 상세](./benchmark-results.md)).

> 범례: **O** 지원, **△** 제한적/수동 설정 필요, **X** 미지원.

## 2. 데이터 지정(binding)과 반복

**마커 지정 방식**부터 다릅니다. **JXLS**는 값 표현식(`${...}`)은 셀 값에 두고, 영역·반복·조건 같은 **커맨드(`jx:area`, `jx:each`, `jx:if`)는 셀 코멘트(노트)** 에 작성합니다. **TBEG**은 반복·변수·이미지 등 **모든 마커를 셀 본문(값)에 직접** 작성합니다. JXLS 방식은 셀 값에 표현식만 남아 깔끔한 대신 커맨드가 코멘트에 있어 템플릿에서 한눈에 드러나지 않고, TBEG 방식은 마커가 셀에 그대로 보여 직관적인 대신 셀 본문을 차지합니다.

**JXLS** — `jx:each` 커맨드가 중심입니다. `items`(Iterable/배열)와 `var`로 반복하며 `direction="DOWN|RIGHT"`로 행/열을 확장합니다. `groupBy`/`groupOrder`로 그룹 반복, `select`로 필터링, 그리고 `jx:each`로 **시트 자체를 동적 생성**할 수 있습니다. `jx:grid`는 컬럼 헤더와 데이터로 표를 동적 구성합니다.

**TBEG** — `${repeat(collection, range, var, direction)}` 마커로 반복하며 방향은 `DOWN`(기본)/`RIGHT` 두 가지입니다. **반복 대상 범위를 다른 시트로 지정**(`'시트명'!A1:B1`)할 수 있습니다. 반면 **동적 그리드·동적 시트 생성은 템플릿 기반 원칙상 다루지 않으며**, 선언적 그룹 반복(`groupBy`)이나 중첩(마스터-디테일) 반복 문법도 제공하지 않습니다. 그룹핑은 데이터를 그룹 기준으로 가공하고 `merge`로 표현하며, 그룹 집계는 Excel 수식(`SUBTOTAL` 등)으로 대응합니다(§6). 컬렉션이 비면 지정한 **대체 영역**을 표시하고, 대체 영역이 단일 셀이면 반복 영역을 병합해 "데이터 없음" 같은 메시지를 보여줍니다 — 실측 결과 JXLS는 빈 컬렉션이면 반복 행을 삭제할 뿐 대체 콘텐츠 기능이 없습니다.

정리하면, **JXLS는 그룹·그리드·동적 시트 등 반복을 변환하는 문법이 풍부**하고, **TBEG은 "템플릿 기반" 원칙에 충실**합니다.

## 3. 템플릿 레이아웃 보존과 데이터 확장

데이터가 확장될 때 양쪽 모두 원본 템플릿의 레이아웃을 보존합니다 — 실측 결과 **JXLS도 열 폭·행 높이를 유지하고, 반복 영역 아래의 내용을 확장량만큼 시프트**합니다. TBEG은 여기에 더해 다음을 명시적으로 다룹니다.

- **주위 요소 자동 위치 보정**: 반복 영역이 확장되면 밀리는 주위 요소(합계 행, 요약 행, 병합 셀, 차트, 이미지 등)의 위치를 확장량에 맞춰 보정합니다. 세로 확장이면 아래쪽, 가로 확장이면 오른쪽 요소가 이동합니다. **반복 영역이 여러 개일 때도 정확합니다** — 세로로 나열된 반복은 각 확장량의 합만큼, 같은 행에 병렬로 놓인 반복 아래의 범위(병합 셀·이름 정의 등)는 걸친 열 중 가장 많이 밀린 확장량(max)에 맞춰 직사각형을 유지하며 보정합니다. 실측 결과 JXLS도 세로 나열 반복의 합산 시프트는 정확하지만, 병렬 반복 아래의 병합 범위는 anchor(첫 셀) 열의 반복만 반영합니다.
- **묶음 이동(bundle)**: `bundle` 마커로 여러 열이나 여러 반복 영역을 하나의 단위로 묶어 함께 이동시키며, 한 묶음 안에 반복이 여럿이면 각 확장량을 합산합니다.
- **영역 무결성**: 반복·묶음·병합 영역은 서로 부분적으로 걸칠 수 없으며 완전히 포함되거나 분리되어야 합니다. 이 제약이 확장 시 레이아웃이 어긋나지 않도록 보장합니다.

레이아웃 보존 자체는 양쪽 모두 되지만, TBEG은 차트·피벗·조건부 서식 등 Excel 네이티브 요소까지 확장에 맞춰 조정하는 범위를 명시적으로 넓혀 두었습니다(§7~9).

**셀 서식 보존**: 데이터 확장 시 셀 서식(배경색·폰트·테두리 등)은 양쪽 모두 보존됩니다 — 실측 결과 JXLS도 확장되는 반복 셀과 그 아래 주위 요소의 서식을 그대로 유지하고, TBEG도 확장되는 셀과 확장에 따라 보정되는 주위 요소 모두 원본 서식을 보존합니다.

## 4. 수식 처리

양쪽 모두 기본적으로 데이터 확장 시 수식 범위를 자동 조정합니다(`=SUM(C3)` → `=SUM(C3:C5)`).
 
TBEG의 조정은 단순 참조 시프트를 넘어 여러 축으로 동작합니다.
- **참조 유형·방향 인지**: 상대·절대·혼합 참조를 구분하여 절대 참조는 고정하고 상대 성분만 조정합니다. 세로 확장에서는 행 절대(`B$3`)를, 가로 확장에서는 열 절대(`$B3`)를 확장 대상에서 제외합니다.
- **단일 셀 → 범위 자동 확장**: `=SUM(C3)`이나 `=SUM(C3:C3)`이 데이터 건수만큼 `=SUM(C3:C5)`로 넓혀집니다.
- **확장과 시프트의 분리**: 반복 영역 안의 수식(각 아이템 행)은 행·열 인덱스만큼 조정하고, 영역 밖의 수식(합계·요약 등)은 확장량만큼 위치를 이동시킨 뒤 참조 범위를 넓힙니다.
- **전방 참조 처리**: 데이터 영역 위에 놓인 수식(상단 요약의 `SUM` 등)도 하단 데이터 확장에 맞춰 조정됩니다. 위치를 사전에 해석적으로 계산하므로, 스트리밍(SXSSF)에서 아직 존재하지 않는 아래 행을 참조하는 수식도 동작합니다.
- **세로·가로 양방향** 반복 모두에서 조정합니다.
- **수식 내 변수 주입**: 템플릿 수식의 인자에 변수 마커(`${...}`)를 넣으면 값이 치환되어 동적 범위·동적 수식이 완성됩니다(예: `=SUM(B${startRow}:B${endRow})`, `=HYPERLINK("${url}", "${text}")`). JXLS의 파라미터화 수식(`$[SUM(E4) * ${bonus}]`)에 대응합니다. 또한 데이터 값이 `=`로 시작하면 수식으로 바인딩되어, 수식 자체를 데이터로 주입할 수도 있습니다.

**JXLS**는 표준 수식 자동 조정(상대 참조 시프트, `SUM(C4)`→`SUM(C4:C8)` 범위 확장)에 더해, 컨텍스트 변수를 주입하는 **파라미터화 수식** `$[SUM(E4) * ${bonus}]`, 서로 다른 영역의 셀을 결합하는 **jointed 참조** `$[SUM(U_(F8,F13))]`, 그리고 **크로스시트 수식 조정**을 제공합니다. 실측 결과 JXLS는 다른 시트의 반복 셀을 가리키는 단일 참조(`=SUM(Sheet2!B2)`)를 그 시트의 확장에 맞춰 `=SUM(Sheet2!B2:B6)`로 조정합니다.

**TBEG도 크로스시트 수식 조정을 지원합니다** — 다른 시트의 반복 셀을 가리키는 참조(`=SUM('데이터'!B3:B3)`)를 그 시트의 확장에 맞춰 `=SUM('데이터'!B3:B5)`로 조정하며, 자기 시트를 접두사로 명시한 참조도 동일하게 확장합니다. **이름 정의(named range)로 지정된 범위를 참조하는 수식**(`=SUM(SalesData)`)도 지원합니다 — named range 정의가 repeat 영역과 겹치면 그 정의를 확장 범위로 갱신하므로, 수식은 그대로 두고 이름이 가리키는 범위만 넓어집니다. 다만 여러 시트에 걸친 3D 참조(`Sheet1:Sheet3!A1`)는 자동 확장되지 않습니다.

정리하면, 수식 내 변수 주입은 양쪽 모두 지원하며(JXLS 파라미터화 ↔ TBEG 수식 내 변수), 같은 시트 범위 조정과 크로스시트 수식 조정도 양쪽 모두 됩니다. TBEG은 참조 유형·방향·전방 참조를 아우르는 **조정의 폭**에, JXLS는 jointed 참조·파라미터화 수식 등 **참조 표현의 범위**에 각각 강점이 있습니다.

## 5. 조건부 렌더링

- **JXLS**: `jx:if` 커맨드로 조건식에 따라 셀 영역을 표시/숨김할 수 있습니다(if / if+else). 데이터 값에 따른 영역 분기가 템플릿에서 직접 가능합니다.
- **TBEG**: **템플릿에 조건식을 작성하는 선언적 조건 분기는 제공하지 않습니다.** 대신 코드에서 조건을 처리하여 같은 결과를 얻습니다. 조건을 만족하는 항목만 `DataProvider`로 제공하면 `repeat`이 해당 항목만 확장하며(행 단위 조건부), `hideable` 마커로 특정 필드나 영역을 조건에 따라 숨길 수 있습니다.

즉 조건부 렌더링의 결과는 양쪽 모두 달성할 수 있으나, JXLS는 **선언적**, TBEG은 코드에서 조건을 처리하는 **명령적** 방식입니다.

## 6. 그룹핑·그리드·동적 시트

JXLS는 `groupBy`(데이터를 그룹으로 묶어 반복), `jx:grid`(동적 그리드), `jx:each` 기반 **동적 시트 생성**을 제공합니다.

**동적 그리드·동적 시트 생성**은 템플릿에 없는 표나 시트를 런타임에 만들어 내는 기능입니다. 디자이너가 작성한 고정 양식에 데이터를 바인딩하는 **"템플릿 기반" 접근과 지향이 다르므로**, TBEG은 이 영역을 의도적으로 다루지 않습니다.

**그룹 반복**은 TBEG에 `groupBy` 같은 선언적 문법이 없지만, 코드 차원에서 대응할 수 있습니다. 데이터를 그룹 기준으로 정렬·가공하여 제공하고 `merge` 마커로 그룹 컬럼을 병합하면, 그룹으로 묶인 표현을 얻습니다. `${merge(emp.dept)}`처럼 지정하면 연속된 같은 부서명이 자동으로 병합되어 그룹 컬럼처럼 표현됩니다. 이 **연속 동일값 자동 병합**은 실측 결과 JXLS에는 없는 기능입니다(JXLS는 같은 값이 이어져도 개별 셀로 기록). 다만 그룹 헤더 행을 하위 항목 위에 별도로 두는 **계층 구조는 중첩 반복을 지원하지 않아 제한적**이며, 이 계층 그룹 반복은 JXLS의 `groupBy`가 선언적으로 제공합니다.

## 7. 차트 범위 조정

- **JXLS**: 차트의 데이터 범위를 자동으로 확장하는 기능이 없습니다. 데이터 증가에 대응하려면 Excel의 **동적 이름 범위**(`OFFSET` 수식 등)를 템플릿에 수동으로 설정해야 합니다.
- **TBEG**: 데이터 확장에 맞춰 **차트 시리즈 범위를 자동 조정**합니다. 단일 셀 참조를 범위로 확장하고 앵커를 이동하며, 막대·꺾은선·영역·원형·분산형·도넛·방사형·거품형 및 3D·주식·표면형 등 광범위한 차트 타입을 지원합니다. 다른 시트의 repeat 확장도 반영합니다.

---

## 8. 피벗 테이블 재생성

- **JXLS**: 피벗 테이블은 템플릿에서 "파일을 열 때 데이터 새로고침"을 활성화하는 방식으로 대응합니다(수동, 사용자가 파일을 열 때 갱신).
- **TBEG**: 원본 피벗을 추출한 뒤 확장된 데이터로 **피벗 캐시를 새로 빌드하여 재생성**하고, 파일을 열 때 별도 새로고침이 필요 없도록 처리합니다.

---

## 9. 이미지·병합·조건부 서식·데이터 유효성

- **이미지**: 양쪽 모두 위치·크기·앵커를 제어합니다. JXLS `jx:image`는 이미지를 영역(`lastCell`)에 앵커하고 `scaleX`/`scaleY`로 크기를 조절하며 PNG·JPEG·EMF·WMF 등 여러 형식을 지원합니다(소스는 `byte[]`). TBEG `${image(...)}`는 위치(셀 지정)와 크기(fit/original/픽셀/비율) 옵션을 제공하며, 소스로 ByteArray 외에 **URL(다운로드 임베딩)과 지연 로딩**을 지원합니다. 위치·크기·앵커 자체는 양쪽 다 되고, 차이는 소스 방식(TBEG의 URL·지연 로딩)과 크기 지정 방식(JXLS 배율 vs TBEG 픽셀/비율/맞춤)에 있습니다.
- **병합 셀**: 양쪽 모두 지원합니다. JXLS는 `jx:mergeCells`/`jx:areaColumnMerge`, TBEG은 `merge` 마커와 반복 밖 병합 셀 위치 자동 조정을 제공합니다.
- **조건부 서식**: 양쪽 모두 데이터 확장 시 조건부 서식을 조정합니다 — 실측 결과 JXLS도 확장된 각 행에 규칙을 복제하여 적용합니다.
- **데이터 유효성(드롭다운·입력값 제한)**: 양쪽 모두 데이터 확장 시 유효성 규칙의 적용 범위를 확장된 행 전체로 넓힙니다. 반복 영역과 겹치는 유효성은 확장 행에 전파되고, 겹치지 않는 유효성은 원본 범위를 유지합니다.

---

## 10. 스트리밍과 대용량 처리

두 라이브러리 모두 Apache POI의 **SXSSF**로 대용량을 스트리밍 처리합니다. 그러나 적용 방식과 제약이 다릅니다.

**JXLS** — 스트리밍은 선택 사항입니다: `STREAMING_OFF`(기본)/`STREAMING_ON`/`AUTO_DETECT`/`streamingWithGivenSheets`. 공식 문서는 명확한 제약을 밝힙니다 — *"1행의 수식이 2행의 데이터를 참조할 수 없다(2행이 아직 존재하지 않으므로)"*. 즉 스트리밍은 **전방 참조 수식이 없는 "단순 데이터 리스트"에만** 쓸 수 있고, *"템플릿마다 스트리밍 가능 여부를 시험해야 한다"* 고 안내합니다.

**TBEG** — **항상 스트리밍**으로 동작하며, 후처리 단계도 스트리밍으로 수행합니다. 데이터 영역 아래에 위치한 **전방 참조 수식**(예: 데이터 하단의 `SUM`)도 렌더링 이후의 수식 조정 단계에서 처리되므로, 수식·차트·피벗이 있는 템플릿에서도 스트리밍이 유지됩니다. 피벗이 없으면 100만 행까지 처리합니다.

이 지점이 두 라이브러리의 구조적 차이입니다. **JXLS는 스트리밍을 "단순 데이터"로 한정**하는 반면, **TBEG은 스트리밍을 기본 경로로 두고 수식·네이티브 요소와 병행**합니다.

---

## 11. 성능 (동일 환경 측정)

동일 환경(Apache POI 5.5.1, JMH fork=1·warmup=1·measurement=3, 3개 컬럼 repeat + SUM 수식)에서 측정한 결과입니다.

|    데이터 크기 |    모드    |   TBEG |     JXLS | JXLS/TBEG |
|----------:|:--------:|-------:|---------:|:---------:|
|   10,000행 |   비스트리밍   |   48ms |    265ms |     5.5배 |
|   10,000행 |   스트리밍    |   48ms |     74ms |     1.6배 |
|   50,000행 |   비스트리밍   |  184ms |  1,332ms |     7.2배 |
|   50,000행 |   스트리밍    |  186ms |    358ms |     1.9배 |
|  100,000행 |   비스트리밍   |  360ms |  2,559ms |     7.1배 |
|  100,000행 |   스트리밍    |  367ms |    727ms |     2.0배 |

측정 워크로드에서는 TBEG이 스트리밍에서 약 2배, 비스트리밍에서 6~7배 빠릅니다. 다만 이는 특정 워크로드에 대한 자체 측정치이며, 템플릿 구성(수식 복잡도, 차트/피벗 유무, 컬럼 수)에 따라 결과는 달라질 수 있습니다. 전체 크기별 수치는 [성능 벤치마크 상세](./benchmark-results.md)를 참조하세요.

## 12. 편의성과 통합

|             항목            | JXLS 3.1.0 | TBEG 1.2.5 |
|:-------------------------:|:----------:|:----------:|
|         비동기 생성            |     X      |  O (코루틴/Future/백그라운드 잡) |
|      Spring Boot 자동 설정     |     X      |     O      |
|    설정 파일(yml/properties)   |     X      |     O      |
|        Kotlin DSL API        |     X      |   **O**    |
|      지연 로딩 데이터 소스          |     X      |     O      |
|      문서 메타데이터 설정           |     X      |     O      |
|      열기 암호(암호화)            |     X      |     O      |

- **비동기 생성**: TBEG은 코루틴·`CompletableFuture`·백그라운드 잡 방식의 비동기 생성을 제공하며, 진행률 콜백과 생성 취소를 지원합니다. JXLS는 비동기 API가 없습니다.
- **Spring 통합**: TBEG은 자동 설정을 제공하여, 의존성만 추가하면 생성기 빈이 등록되고 설정 파일(`hunet.tbeg` 접두사)로 옵션을 연동할 수 있습니다. JXLS는 별도 통합 코드를 작성해야 합니다.
- **데이터 소스**: TBEG은 전체 적재(Map)와 **Iterator 기반 지연 로딩**을 모두 지원하여, 대용량에서 아이템을 하나씩만 메모리에 유지할 수 있습니다. JXLS는 컨텍스트 Map에 데이터를 담아 전달합니다.
- **언어 지원**: 양쪽 모두 JVM 라이브러리라 Java·Kotlin 어디서나 호출할 수 있습니다. JXLS는 Java로 작성되어 Java 관용 API를 제공하고, TBEG은 Kotlin으로 작성되어 Kotlin DSL(`simpleDataProvider { ... }`)과 코루틴 기반 비동기를 제공하면서 `@JvmOverloads`·빌더 등 Java 상호운용 API도 함께 제공합니다.
- **문서 메타데이터·암호화**: TBEG은 제목·작성자·회사·관리자 등 문서 속성을 빌더(`DocumentMetadata`)로 설정하고, `password` 인자로 열기 암호(OOXML 암호화)를 걸 수 있습니다. JXLS는 이를 전용 API로 제공하지 않아, 필요하면 하부의 Apache POI를 직접 사용해야 합니다.

## 13. 선택 가이드

**JXLS이 적합한 경우**
- `jx:if` 같은 **범용 조건부 렌더링**, **그룹핑·동적 그리드·동적 시트 생성**, **중첩 반복**이 필요할 때
- **jointed 참조**(`U_()`)나 **파라미터화 수식 문법**($[...]) 등 JXLS 고유의 수식 표현이 필요할 때
- 성숙한 커뮤니티와 기존 JXLS 자산을 활용하고 싶을 때

**TBEG이 적합한 경우**
- 보고서에 **차트·피벗 테이블**이 포함되고, 데이터 확장 후에도 자동으로 조정되어야 할 때
- **빈 데이터일 때 대체 콘텐츠 표시**나 **연속 동일값 병합** 같은 표현이 필요할 때
- **수식이 있는 대용량**을 스트리밍으로 안정적으로 처리해야 할 때(전방 참조 포함)
- **비동기 생성**이나 **Spring Boot** 통합이 필요할 때

두 라이브러리는 지향점이 다릅니다. **데이터 변환 로직의 표현력**(조건부 렌더링·그룹핑·동적 구조)이 우선이면 JXLS, **차트·피벗의 자동 조정과 대용량 스트리밍·통합**이 우선이면 TBEG이 유리합니다. 레이아웃 보존·조건부 서식·데이터 유효성 확장·수식 범위 조정·크로스시트 수식 등 다수 기능은 양쪽 모두 지원하므로, 위의 갈리는 항목을 기준으로 선택하는 것이 실용적입니다.
